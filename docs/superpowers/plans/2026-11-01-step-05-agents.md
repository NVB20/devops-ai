> **Note (2026-11-01):** The code now in `05-Agents/` was written in a parallel session, and its details differ from this plan. The agent loop streams the LLM reply, a clarifying question starts with a `CLARIFY:` marker, and the stream events are `llm` / `tool` / `token` / `reasoning` instead of `searching` / `search`. The goal, graph, search cap, formats and test questions are the same.

**Goal:** Turn the two step 04 answer nodes into two real agents, a Troubleshooting Agent and a Knowledge Agent. Each has its own prompt and answer format, and each searches the runbooks itself through a `search_runbooks` tool, up to 3 times.

**Architecture:** `05-Agents/` is a copy of `04-LangGraph/`. The graph becomes `START → classify → {off_topic | troubleshoot | knowledge} → END`, and the `retrieve` node goes away. Both agents share one tool-calling loop, `run_agent(system_prompt, question)`. It calls the LLM with the `search_runbooks` tool (OpenAI function-calling format, through OpenRouter), runs each search the model asks for, and stops after 3 searches by sending `tool_choice="none"`. Each search is pushed to `/chat/stream` as a LangGraph custom stream event, so the UI can show it live.

**Tech Stack:** FastAPI, LangGraph 1.2 (`stream_mode=["tasks", "custom"]`, `get_stream_writer`), the OpenAI client pointed at OpenRouter (`tools=`), Postgres + pgvector, pytest with a fake LLM.

## Global Constraints

- No new dependencies. The agent loop is hand-written on the OpenAI client already in use, with no `langchain-openai`.
- The database, `chunks` table and `ingest.py` stay the same as step 03/04. Nothing new to ingest.
- `04-LangGraph/` stays as it is, including its uncommitted GPU Whisper changes. All work happens in `05-Agents/`.
- The step 0 tool-calling check is done: the `OPENROUTER_MODEL` in `.env` supports `tools`.
- Max searches per agent: `MAX_SEARCHES = 3`.
- Troubleshooting format, always in this order: `Likely cause:` → `Check:` → `Fix:` → `Escalate if:`. A vague question gets one clarifying question instead.
- Knowledge format: a short explanation, then `Steps:`, and it may combine several runbooks.
- Both agents cite runbooks like `[disk-full.md]`, and `sources` lists the cited files.

def reply(content=None, queries=()):
    calls = [SimpleNamespace(id=f"call_{i}", type="function",
                             function=SimpleNamespace(name="search_runbooks", arguments=json.dumps({"query": q})))
             for i, q in enumerate(queries)]
    return SimpleNamespace(model="fake-model", choices=[SimpleNamespace(message=SimpleNamespace(
        role="assistant", content=content, tool_calls=calls or None))])


def fake_llm(route, agent_replies=(), calls=None):
    """Classify gets `route`; agent calls get agent_replies in order (the last one repeats). calls records each request."""
    replies = list(agent_replies) or [reply("1. do it [a.md]")]
    def create(model, messages, **kwargs):
        if calls is not None:
            calls.append({"messages": [dict(m) for m in messages], **kwargs})
        if messages[0]["content"] == main.CLASSIFY_PROMPT:
            return reply(route)
        return replies.pop(0) if len(replies) > 1 else replies[0]
    return SimpleNamespace(chat=SimpleNamespace(completions=SimpleNamespace(create=create)))

```python
MAX_SEARCHES = 3  # per agent per question

TROUBLESHOOT_PROMPT = """You are the Troubleshooting Agent of our DevOps team: something is broken and the user wants it fixed.

If the question does not say WHAT is broken (e.g. "something is broken", "it doesn't work"), do not search and do not guess:
reply with exactly one short clarifying question and nothing else.

Otherwise find the fix with the search_runbooks tool. You can search up to 3 times. Use your own short, specific wording,
and search separately for each symptom when there are several (e.g. "pods pending" and "node NotReady").

Answer ONLY from the search results. Never add commands that are not in them. Plain text, no tables, exactly these four parts:
Likely cause: one or two sentences.
Check: numbered steps with the exact commands.
Fix: numbered steps with the exact commands.
Escalate if: when to hand it over, and to whom if the runbook says.
Cite the runbook file after each step, like [disk-full.md]. When several runbooks apply, use all of them and cite each.
If the searches find nothing that fits, say you couldn't find it in the runbooks."""

KNOWLEDGE_PROMPT = """You are the Knowledge Agent of our DevOps team: the user wants to know how something works or how we do it.

Find the answer with the search_runbooks tool. You can search up to 3 times. Use your own short, specific wording,
and search again with other words when the first results don't cover the whole question.

Answer ONLY from the search results. Never add commands that are not in them. Plain text, no tables:
first a short explanation (2-3 sentences), then "Steps:" and numbered steps with the exact commands.
Combine several runbooks when the answer is spread over them.
Cite the runbook file after each step, like [deploy-and-rollback.md].
If the searches find nothing that fits, say you couldn't find it in the runbooks."""

NOT_FOUND_ANSWER = "I couldn't find anything about this in the runbooks."

# The tool as the LLM sees it (OpenAI function-calling format, which OpenRouter passes on to the model)
SEARCH_TOOL = {
    "type": "function",
    "function": {
        "name": "search_runbooks",
        "description": "Search our DevOps runbooks by meaning. Returns the closest runbook sections, "
                       "each starting with its file name in brackets, like [disk-full.md].",
        "parameters": {
            "type": "object",
            "properties": {"query": {"type": "string", "description": "What to look for, e.g. 'pod stuck in Pending'"}},
            "required": ["query"],
        },
    },
}


def search_runbooks(query: str) -> list[dict]:
    """The agents' tool: the step 03 search, called with the agent's own wording."""
    return search(query)


def tool_result(chunks: list[dict]) -> str:
    """What the LLM reads back from a search."""
    if not chunks:
        return "No runbook section matched. Try other words."
    return "\n\n".join(f"[{c['source']}]\n{c['text']}" for c in chunks)


def run_agent(system_prompt: str, question: str, on_search=None) -> dict:
    """The agent loop: the LLM calls search_runbooks as often as it likes (max MAX_SEARCHES), then answers."""
    on_search = on_search or (lambda event: None)
    messages = [{"role": "system", "content": system_prompt}, {"role": "user", "content": question}]
    searches, seen = [], set()  # seen: every runbook the searches returned
    while True:
        can_search = len(searches) < MAX_SEARCHES
        # Out of searches: "none" makes the model answer with what it has
        response = client.chat.completions.create(
            model=MODEL, messages=messages, tools=[SEARCH_TOOL], tool_choice="auto" if can_search else "none",
        )
        message = response.choices[0].message
        if not message.tool_calls or not can_search:
            break
        messages.append({
            "role": "assistant", "content": message.content or "",
            "tool_calls": [{"id": c.id, "type": "function",
                            "function": {"name": c.function.name, "arguments": c.function.arguments}}
                           for c in message.tool_calls],
        })
        for call in message.tool_calls:
            if len(searches) == MAX_SEARCHES:  # one reply can ask for more searches than are left
                content = "Search limit reached. Answer with what you have."
            else:
                try:
                    query = json.loads(call.function.arguments or "{}").get("query") or question
                except json.JSONDecodeError:
                    query = question
                on_search({"type": "searching", "query": query})
                started = time.perf_counter()
                chunks = search_runbooks(query)
                hits = [{"source": c["source"], "similarity": c["similarity"]} for c in chunks]
                searches.append({"query": query, "chunks": hits, "ms": ms_since(started)})
                on_search({"type": "search", **searches[-1]})
                seen.update(c["source"] for c in chunks)
                content = tool_result(chunks)
            messages.append({"role": "tool", "tool_call_id": call.id, "content": content})

    answer = (message.content or "").strip() or NOT_FOUND_ANSWER
    # Only the runbooks the answer cites. A clarifying question cites none, so it gets no sources
    sources = sorted(s for s in seen if s in answer)
    return {"answer": answer, "model": response.model, "sources": sources, "searches": searches}
```
